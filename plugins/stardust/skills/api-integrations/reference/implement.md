# Implementation reference

Implementation happens in the EDS repo after the Phase 3 report gate and CORS probe.

## Generate contract clients

Run the generator from the EDS repo:

```bash
node scripts/api-codegen.mjs --contracts stardust/api/contracts --out .
```

Useful options:

- `--id contact-form,search` limits generation to selected contract ids.
- `--dry-run` prints planned files without writing.
- `--force` overwrites an existing `scripts/api/<id>.js` file that does not carry the generated marker.

The generator writes `scripts/api/<id>.js` for eligible contracts and creates `scripts/api-config.js` only when it is absent. Re-running overwrites generated modules whose first line is the marker:

```js
// Generated by api-integrations api-codegen from contract <id>. Edits are overwritten on re-run.
```

Owner-edited files without the marker are skipped unless `--force` is passed. `scripts/api-config.js` is never overwritten, because credentials and deployment base URLs remain owner-managed.

## Base URL config

Create `scripts/api-config.js` as owner-editable indirection from page host to API base URL. Typical shape:

```js
const API_BASES = [
  { match: /localhost|\.aem\.page$|\.aem\.live$/i, base: 'https://source.example.com' },
  { match: /.*/, base: '' },
];

export function apiBaseFor(hostname = window.location.hostname) {
  return (API_BASES.find((entry) => entry.match.test(hostname)) || API_BASES.at(-1)).base;
}
```

Production can use `''` for relative requests behind the customer CDN. `localhost`, `aem.page`, and `aem.live` usually point to the source/API origin until the backend allows the new origins.

The generated config includes `apiHeadersFor(id) { return {}; }` and comments listing required header names per contract. Ask the owner for values and fill them there; never copy captured values or commit secrets.

## Client module

The generated `scripts/api/<id>.js` exports:

- `FIELDS`: `{ path, name }` entries for form-control mapping. Selectors and test values are intentionally omitted.
- `buildPayload(values)`: pure helper that builds the captured request body shape from flat values keyed by field-map path.
- default `call(values, { signal })` plus a camelCase named alias, returning `{ ok, status, data, error }`.

Example call pattern:

```js
import submitContact, { FIELDS } from '../../scripts/api/contact.js';

const values = Object.fromEntries(FIELDS.map(({ path, name }) => [path, form.elements[name]?.value || '']));
const result = await submitContact(values, { signal });
```

The generated module preserves captured content type, method, payload shape, GraphQL operation/variables, query keys, and client dependencies. reCAPTCHA tokens are requested fresh per call. Cookie, title, and location dependencies are read at request time. Header values, cookies, real tokens, selectors, and field-map test values are not generated.

Generation fails with exit 1 when a selected contract needs unsupported client dependency kinds, or when a GraphQL contract has neither a query document nor a persisted-query hash.

## Binding and extension points

Use project-owned code and extension points:

- Prefer the top Block Party match when it fits; adapt through documented extension points.
- Never edit vendored code or copied third-party libraries.
- For the AEM Forms engine, use a form definition plus project-owned custom functions through `customFunctionsPath`.
- If a form is rendered by existing project code or later by the form engine, use a project-owned capture-phase `submit` binder so the API handler runs before default handlers without forking the form engine.

## UI behavior and validation

Replicate captured UI behavior: success/error message placement, reset behavior, disabled/loading state, dataLayer events, and list/result counts for read integrations. Add client validation that mirrors observed server rules such as minimum length, required fields, email/phone formats, and enum choices.

If credentials, CORS, or backend ownership remain unresolved, ship the safe interim state and name the owner decision in `stardust/api/report.md` and parity output.
