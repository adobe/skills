# Phase 5 handoff — contract card (migrate → deploy → rollout)

Everything the replica Phase 5 executor needs from the three sibling skills — rules, commands, exact ledger strings — so no sibling document is read whole. Paths are relative to this file.

## 1. Migrate — sibling tier (every non-archetype page of a gated template)

Siblings inherit the archetype's source-fidelity gate; they re-check only what varies per page: content, media, the delivery contract (`../../migrate/reference/fidelity-tiers.md § The three tiers`). The reflex for "page N of a template" is the archetype's map (row 2) or a fork of the archetype, never re-author. **Order (#126): a template's siblings encode or render only after its archetype is LIVE and gated at the published origin** (§ 3 row C, unit `C-archetype`) — they inherit a proven map or encoder, not a prototype; a recorded run migrated 78 siblings from unproven archetypes and re-deployed whole families.

## 2. Deploy — per page

**Editability contract — node-slotting, never value-slotting** (`../../deploy/SKILL.md § Experience Workspace editability contract`):
- EW1 MOVE authored `h1–h6 / p / ul / ol / pre / blockquote / picture / img` with `append()`/`prepend()`; never rebuild from `textContent`/`innerHTML`, never `cloneNode` + discard, never retag, never `.trim()` displayed text; capture `nextElementSibling` before `append()`.
- EW2 wrappers carry the layout classes; style the authored element through descendant selectors (`.headline :is(h2, h3)`), never a class on it, never `>` / `:first-child` / `:nth-child` on the path to it.
- EW3 CTAs move as their `<p>`. EW4 presentational clones get `stripInstrumentation()`. EW5 exempt text is declared `@ew-exempt <reason>` in the block JSDoc, never dropped. EW6 card-as-link unwraps the inner anchor after reading `href`. EW7 no `<button>`/`<summary>` hosts authored text. EW8 reabsorbed section heads move the wrapper's children. EW9 `decorate()` is re-entrant. EW10 default-content selectors follow the same rules.
- Banned: `slot.textContent = cell.textContent`, `${text}` template interpolation — renders pixel-perfect and is 100 % uneditable (`../../deploy/SKILL.md § Anti-patterns`).

**Decode tier per section** (`../../deploy/SKILL.md § 2b. Section schema`; record the tier in `stardust/eds-conversion-log.md`):
- Template-slotted — replica's default for fixed compositions (hero, band, stat row, chrome): the prototype section's inner DOM as a template of EMPTY slot containers; authored nodes MOVED into them by role.
- Reconstructive — repeat groups only (cards, listings, FAQ): classify by content, never `rows[N]`; segment on the most frequent heading tag; consume every element type or end with a leftovers pass (`../../deploy/SKILL.md § 8. Block JS scaffold`).
- Both tiers, in order: `node stardust/scripts/deploy/section-schema.mjs <protoURL> --out stardust/eds-schema/<page>.json` → write rows and `decorate()` from it → per block `node stardust/scripts/deploy/block-roundtrip.mjs <protoURL> content/<page>.html --blocks <name> --ew` exit 0 (0 structural 🔴, 0 DEAD TEXT / DROPPED CONTENT / DUPLICATED INDEX) → one whole-page run without `--blocks` before any PUT (`../../deploy/SKILL.md § Local QA before deploy`). An encoded sibling skips these three local launches only under `../../migrate/reference/fidelity-tiers.md § Encoded siblings` (the skip rule, reading it after encoding, recording a pass).

**DA media protocol** (`../../deploy/SKILL.md § Images: editorial`):
- Editorial image (anything carrying meaning, hero/CTA backgrounds included): `PUT https://admin.da.live/source/{org}/{repo}/media/<scope>/<file>` — multipart, field name `data`, correct `Content-Type`; JPG/PNG/webp source only; SVG only if pure-vector and under ~40 KB. One command does the whole folder or manifest and prints the URL to author per file: `DA_TOKEN=… node stardust/scripts/deploy/da-media-upload.mjs --org <org> --repo <repo> --scope <name> --dir stardust/current/assets/media` (`--scope` is the folder UNDER `media/`, never `media/<name>` — the path would double and the script refuses it; § 4 table; never a hand-rolled PUT loop).
- Author `<img src="https://content.da.live/{org}/{repo}/media/<scope>/<file>" alt="…">` in the cell; never `/img/…` in content, never imagery baked into block JS by index. Decorative = CSS only.
- Never anonymous-curl `content.da.live` / `admin.da.live` URLs — a 401 there is normal and ingests fine. Verify post-preview only: delivered `.plain.html` has 0 `about:error` and the expected `<img>` + alt count (`../../deploy/da-deploy-protocol.md § Deploy .DA Source API`, step 3b).
- Source-CDN 403/401 = bot wall, NOT missing → rehost from the CAPTURED src (`stardust/current/assets/media/`); omit only on a true 404 after the rendition / `?`-delimiter repairs; when `_crawl-log.json#discovery.fetchTechnique` is `headed-chrome`, verify with the in-page fetch, never a bare curl.
- Images only: video / audio / PDF never ride `content.da.live` (anonymous visitors get 401) — serve them root-relative from the code origin.

**DA deploy protocol** (`../../deploy/SKILL.md § Deploy .DA Source API`; `../../deploy/da-deploy-protocol.md § Deploy .DA Source API`):
- Preconditions: code branch pushed (Code Sync builds it — force with `POST https://admin.hlx.page/code/$ORG/$REPO/$BRANCH/*` → 202 when edited blocks 404, then poll with `fresh-check.mjs <edited block .js url> --grep '<marker>'`); host label `<branch>--<repo>--<org>` ≤ 63 chars; `DA_TOKEN` preflighted (JWT `exp`) and re-checked before each batch — a mid-batch 401 checkpoints the ledger and halts with one instruction, never fails pages red.
- Per-page atomic chain, in order: `localize-links.mjs --source-host <live-host>` — with `--unit <unit>` inside a unit with pages (only its documents are written; the map still spans the whole tree), else over the whole tree (C0's foundation sub-units included) — then the same with `--check` exit 0 → `davids-model-lint.mjs` exit 0 → `sanitise.js` → `PUT https://admin.da.live/source/<org>/<repo>/<path>.html` (multipart `data`, `type=text/html`, expect 201) → `POST https://admin.hlx.page/preview/<org>/<repo>/<branch>/<path>` (200) → GET `.plain.html`: 200, `<body>` wrapper, one `<h1>` (none when the source capture has none — a recorded source trait, never a content edit), 0 `about:error`, no `/img/` → `ai-readability.mjs` code score ≥ 98 → computed-style guard once per template (grid/flex blocks compute `grid`/`flex`, `main .section` > 0, `data-block-name` present, 0 pageerror, every visible image `clientWidth > 0`) → only then `deployed`: `update-coverage.mjs <slug> --status deployed --url <preview url>`, then, inside a C-deliver unit, `unit-commit.mjs <unit>` — before any published-origin gate (D2-built pages and `foundation-chrome`'s chrome documents are recorded, then committed at the checkpoint commit, § 5). Admin 200 ≠ delivered.
- Publish always: every delivered page, the redirects sheet and the chrome documents go live (`PUT → preview → live`; `deploy-batch.mjs` without `--no-publish`), as `../../rollout/SKILL.md § Phase C` requires — query indexes and chrome build from the live tree.
- More than a few pages: `deploy-batch.mjs`, never a hand-rolled loop; after a transient blip re-run the same command (the ledger skips live pages whose document is unchanged).

**Boilerplate lint — satisfy it up front, not at commit time.** Blocks and styles lint under the project's own config; never add an `.eslintignore` for runtime files (`../../deploy/SKILL.md § Target runtime`). For the stock boilerplate that is ESLint airbnb-base + Stylelint standard, both blocking: kebab-case CSS class names and selectors; one statement per line — expand one-line multi-statement rules and arrow bodies, the recorded failure class (`../../../../aem/edge-delivery-services/skills/building-blocks/references/css-guidelines.md § Naming Conventions`; `../../../../aem/edge-delivery-services/skills/code-review/references/review-checklist.md § Linting & Style`, `--all`). Once before the checkpoint commit: the boilerplate's own `npm run lint:fix` (its `lint:js -- --fix && lint:css -- --fix`, over `.` and `blocks/**/*.css` + `styles/*.css`), then `npm run lint` — paste only the remaining errors into the conversion log. **Target breakpoints set** (`DESIGN.json` `extensions.breakpoints.target`): C0 adds `"lint:breakpoints": "node stardust/scripts/replica/breakpoint-lint.mjs"` to `package.json` and appends `&& npm run lint:breakpoints` to `lint`, so every lint pass of deploy and rollout fails on an off-target `@media` width or JS threshold (`preserve-direction.md` § 4).

**Final gate runs against the PUBLISHED origin**, per delivered page, judged in the published-origin regime — harness numbers understate (`source-fidelity-gate.md § The published-origin gate`) — and never on the harness before the first PUT: the local harness feeds the structural asserts above (`qa-gate.mjs`, `block-roundtrip.mjs --ew`) and nothing pixel-shaped; the delivery pipeline folds section metadata and serves the media the harness cannot, so a harness pixel number is not a verdict and iterating CSS against it is budget spent without a page (`../../deploy/SKILL.md § Local QA before deploy`, scope boundary). The order is: deploy the representative page first, judge it on the preview origin, fix, redeploy — block CSS/JS rides the code-branch push, a content fix re-PUTs that one page (`deploy-batch.mjs`, above). Header and footer bands each ≤ 2 % via `crop-compare.mjs`, at least once per template (`../../deploy/SKILL.md § Step 10 — Reconcile on the DEPLOYED URL`).

## 3. Rollout — phases A to I (`../../rollout/SKILL.md § Procedure`)

**Unit briefs carry an absolute clock, not a relative budget** (row C's subagent briefs; recorded: units launched late were cut by the session end). `deadline:` (UTC `HH:MM`) = the earlier of the unit's own budget (launch + row C's 90-minute target, or a shorter one the main agent sets) and the session end − 5 min; session end = a boundary reply's time (§ 5) − the elapsed time it names + 90 min (no reply has named one yet → the unit's own budget alone). `expected:` = the main agent's estimate (gate-all's roster estimate for a gate run, else a recorded unit of its kind):

```text
deadline: 21:25 UTC
expected: 45 min
If the deadline cannot be met, stop at the next clean point, flip your unit entry to `paused` with what remains, and return.
```

`paused` on disk: the entry stays `running`, its verdict set by `node stardust/scripts/stardust/progress.mjs unit start <unit> --verdict "paused: <what remains>"` (the pause file's form, below); a resumed session re-runs it like any in-flight unit (§ 5). Launch + `expected` past a known session end − 5 min → not launched (it waits for the next session), unless resumable (`gate-all --skip-existing`, encoder batches) — then launched with the session deadline, pausing at it. Example: a reply at 21:04 UTC names 64 min elapsed → session 20:00–21:30; a cluster sub-unit at 21:05 (own budget 22:35) gets `deadline: 21:25`; `expected: 45 min` → 21:50 → not launched; another template's sub-unit whose remaining work is its `gate-all --only <its pages> --skip-existing` run is resumable → launched with `deadline: 21:25`, pauses there, the next session resumes it.

- **A propagation wait is `node stardust/scripts/deploy/fresh-check.mjs <url> --grep '<marker>'`** (or `--expect-file <f>`; checks ≤ 5 s apart, capped at 180 s; exit 3 = stale) — never a bare `curl -sf` poll; a raw fallback is `curl -s --compressed` (assets are gzip-encoded).
- **Schedule — a unit starts the moment it is unblocked:** once C0 is committed and frozen, every archetype unit starts in the same turn (a background subagent each), each cluster (its first sub-unit) the moment its archetype is `done`; never serialize disjoint units to spare browsers — the browser slot queue paces captures, not the number of units. The lead's loop: `progress.mjs wait` → `progress.mjs show --waves` → for each unit that ended since (an end between two waits goes unprinted), § 5's other steps — block records, freeze check, `unit-commit.mjs <unit>` (commits the flip and records), boundary ask — then `unit start` and spawn everything its `can start now:` line names (the brief carries the clock, § Unit briefs) → wait again; C-final only once that line names `gate-all` (a wait's exit 2 is no signal). The one exception: a unit that edits a shared file waits for that file's lock as the shared-ledgers bullet describes — inside its writer, never by starting later. Each unit records its own end: its subagent's LAST act, after its `unit-commit.mjs`, is `node stardust/scripts/stardust/progress.mjs unit done|failed <unit> --kind <k> --pages <n> --blocks <n> --verdict "<its verdict line>" [--set gates.<w>=<json>]` (not on a paused return), so the lead's wait sees it within 5 s; the lead marks `unit failed <unit> --verdict "<reason>"` only a unit whose agent returned (its line in `stardust/.labs/wake`, or the harness's agent status) without flipping it — at a wake (77) or, a wake can be lost, at a 75 or `show --waves` once past its launch `deadline:` (`"no end by its deadline: <reason>"`). Example: `../../rollout/SKILL.md § Phase C`.
- **Pause file** (`STARDUST_PAUSE_FILE`, JSON `{at, reason}`, created by a supervising process): variable set → every fan-out subagent checks the file at each batch or iteration boundary; present → it finishes the iteration, writes its report and returns. Unset = no check. The file is the supervisor's — the run never writes, edits or deletes it; a relative path is read from the project root. A paused unit is recorded `running`, its `verdict` the report prefixed `paused:`; a resumed session re-runs it like any in-flight unit (§ 5). While the file exists no new unit starts; the main agent records each return in § 5's order and asks its boundary once the last fan-out subagent has returned. Both waits end at once while the file exists (exit 76).
- **Every tool call within the prompt cache's life, the main agent's included:** wait in steps of at most five minutes, lead and subagents alike — `run-bg.mjs wait` for jobs, `progress.mjs wait` for units; a `sleep` is never a wait (`--max 240` where the cache holds five minutes; the shell call's timeout above the wait; exit 77 = the runner's wake line (`stardust/.labs/wake` grew: a background agent finished); the master card's wait discipline). A long instrument (gate.sh rounds, pixel loops, Playwright captures, deploy batches) goes through `run-bg.mjs start`, and `wait` (the caller's own jobs — its agent process's — unless named or `--all`; agents sharing one process name their jobs (`wait <job>…`) or prefix each run-bg call with `RUN_BG_OWNER=<unit>`) is the NEXT tool call; never two long instruments as parallel tool calls in one turn, never two `wait`s in one command.

| `stardust/scripts/thumb.mjs` | `<png\|dir…> [--width 480] [--max-height 3200] [--max-bytes 150000] [--min-share 60] [--offset 0] [--out <dir>] [--suffix -thumb]` | one box-filtered thumbnail per capture, `<src>: <W>x<H> -> <w>x<h> [scaled to <w>px] [(cropped at <n>px of <H> = <share>%)] [for --max-bytes <b>] -> <dst> (<bytes> bytes)`; over `--max-bytes` it goes narrower first (400, 320, 240 px — the whole page), then crops by measured size, never below `--min-share` of the page; a share below 100 → the rest with `--offset <n>` (`<dst>` gains `-<n>`) — read a thumbnail into the context only after this has written it |

## 5. Bookkeeping

Ledger lines go through the master's writer — copy `../../stardust/scripts/ledger.mjs` and `../../stardust/scripts/state.mjs` to `stardust/scripts/stardust/`; one command appends one conformant line to `stardust/status.jsonl` and echoes it. Contract: append-only; one `start` + one `end` per phase, and the `start` line is the FIRST command of the phase, before any script of it runs (`--strict` refuses an `end` without an open `start`); `blocked` with the reason before any halt; every `end` has a section in `stardust/journal.md` headed `## <Phase name> — <what happened> (<date>)` (`ledger.mjs … end` warns when it is missing); file created on first write (`../../stardust/reference/run-status.md § Line shape`; `§ Rules`; `../../stardust/reference/journal-format.md § Entry format`). `--strict` turns an unknown phase into exit 2 instead of a warning.

```bash
L="node stardust/scripts/stardust/ledger.mjs"
$L replica handoff start --strict
$L rollout A-inventory start --strict;  $L rollout A-inventory end --detail "<n> pages" --artifact stardust/rollout/coverage/pages.json --strict
#   … one start/end pair per phase, strings from § 3: B-block, B2-dynamic, C-deliver, (gap-closure — only on pages_failed after C-final), D-site, D2-dynamic, (D3-multilingual), E-full-site, E2-link-audit, F-optimize, G-aem, H-report …
$L rollout C-deliver blocked --detail "DA_TOKEN expired (401) — ledger checkpointed" --strict     # failure path: emit, then halt
$L rollout I-dashboard end --artifact stardust/rollout/dashboard/index.html --strict               # the line supervisors wait for
node stardust/scripts/rollout/done-check.mjs                                                       # exit 0 before handoff end — below
node stardust/scripts/stardust/token-ledger.mjs                                                    # stardust/usage.md + usage.json, committed; no transcripts → `unknown` cells
$L replica handoff end --detail "<n> pages delivered; published-origin gate <result>[; residuals: <list>]" --artifact stardust/rollout/ --strict
$L last rollout                                                                                    # read back the latest rollout line
```

**`replica handoff end` only on `done-check.mjs` exit 0** — or when, after the `gap-closure` phase, its residuals are the only gaps left (`pages_failed` and their units' `unit_unproven`): `handoff end` then names them in its `--detail`, never withheld, never a second loop. Otherwise close each gap with its own remedy and run it again: `pages_not_live` → publish them; `pages_failed` → the `gap-closure` phase (§ 3), once; `gates_inconclusive` → re-capture (a polluted capture has no verdict; never flip it by hand); `pages_unfinished` → deliver the rows; `open_p1` → F-optimize; `header_parity` / `header_parity_errors` → fix or decide every error (hands-off: you decide, with a reason — **Header findings** below): fix the header block, re-explore the live header and re-compare (`../../diff/SKILL.md` § The header contract); `rollout_incomplete` → finish the rollout; `export_stale` → row I's three export commands again, in order; `pages_overridden` → each override needs a `## R-<nn>` entry in `stardust/replica/inconsistency-register.md` referenced by its `overrides.json` reason (tier-shift only, clip and content passing), else the page returns to its fix rounds — above 10 % of delivered pages the template goes back to fix rounds, not more overrides; one `not validated by gate-all` → re-run gate-all so the override carries `valid: true`; `unit_unproven:<unit>` → re-gate the unit's pages at both widths (`gate-all.mjs --only <its pages> --eds-host <preview host>` and `--width 360`), `update-coverage.mjs --gate …` with both widths' tables (each records its width's verdict in `delivery.gate.passByWidth`; a unit is proven only when every width passed — a row gated before that falls back to `pass`, with a `skipped:` line), `unit-commit.mjs <unit>` — or reopen the unit `running`; `sidecars_missing` → `section-schema.mjs … --out stardust/eds-schema/<slug>.json`, the missing gate width, the redirects line (`seed-redirects.mjs`, or the path-safety gate's `stardust/redirects.tsv` row; a line in `stardust/redirects-cdn.tsv`, where the seed routes sources the sheet cannot match, counts too); `ledger_unpaired` → `ledger.mjs check` names them; the ledger is append-only, so re-record the phase: its `start` line, the phase's closing check, then its `end`. A gap only the site owner can close is a `blocked` line naming it, not the `end` line. A planned page the source no longer serves (a 404 at crawl or gate time) is excluded, never dropped: `state.mjs exclude <slug> --reason "<what the source answered>"` (`--url <url>` for one init never had), then `inventory.mjs` — done-check names it `info: pages_excluded`, not a gap.

**Header findings** (the rule of `../../diff/SKILL.md` § The header contract, word for word): Fix or decide every error (hands-off: you decide, with a reason). In a hands-off run (`stardust/state.json` `handsOff: true`) the agent is the deciding party: `chrome-compare.mjs decide <finding> --decision accept|fix-later|artefact --reason "<r>"` signs `{ finding, decision, reason, by: "agent", at }` into `stardust/chrome/header-decisions.json`, one exact finding key per entry, with a reason of at least 40 characters naming the evidence (a measurement artefact, a host-bound feature, a third-party component, a hide-list offset); chrome-compare counts it as decided and lists it in `decidedByAgent` for the owner's review. In an attended run (`handsOff` false or absent) only the site owner clears a finding (`by`, `at`); an agent-signed entry is ignored and reported. So in a hands-off run a header finding is never a `blocked` gap: a proposals file is no decision — each proposal becomes a `decide` or a fix, and `handoff end` lists the decisions the agent took.

Page status: pages migrate delivered advance to `migrated` through the lifecycle writer, never a hand edit — `node stardust/scripts/stardust/state.mjs advance <slug…> --to migrated --migrated <path> --skill migrate` (`../../stardust/reference/state-machine.md § Page lifecycle states`).

Checkpoint commit — wherever no fan-out subagent runs: the end of a phase, of every migrate unit, and inside C-deliver the ends of `foundation-chrome` and `foundation-styles` (no fan-out yet; `unit-commit.mjs` refuses the frozen `blocks/header` / `blocks/footer`), C0's freeze and C-final (a C-deliver unit with pages, `archetype-<template>` included, commits through `unit-commit.mjs`, below); git repos only; the ignore guard is master Setup step 6 — its `stardust/.gitignore` tracks the gate's JSON under `stardust/replica/gates/` (summary, overrides, presence, rounds, triage, probes) and leaves its images untracked, so a lost container keeps the row of record; the push is deploy's Code stage (`../../stardust/SKILL.md § Hands-off mode`; `§ Setup`; `../../deploy/SKILL.md § Deploy .DA Source API`):

```bash
git check-ignore -q .env && ! git check-ignore -q stardust/state.json && git add -A && git commit -qm "replica phase 5 handoff: <what landed>" && git push
```

C-deliver units (§ 3 row C; a sub-unit is a unit here) — per unit, in this order: the block records, the `progress.json` write, the mechanical check, the checkpoint commit, the boundary ask, THEN the next unit. As each subagent returns (C0's included), run steps 0–3 below for its unit at once; never spawn a unit in the same turn after an ask; while subagents run, wait in bounded checks (≤ 4 min each), never one blocking call. A unit end is the only point where a supervised session ends without losing work: the unit is on disk and committed, and a session resumed inside C-deliver starts from `stardust/rollout/progress.json` and runs only the units not `done` (an in-flight unit re-runs from its recorded state — live pages are re-verified, not re-authored). A boundary ask names any other unit still `running`. A unit end is a safe resume point, not a stop: the session ends only for the master card's reasons or when its supervisor ends it at the boundary ask.

```bash
node stardust/scripts/rollout/update-coverage.mjs --block <id> --status converted --eds-name <name>   # 0. each block the unit converted (default content: --eds-name default-content); done-check's info: blocks_pending names any left
node stardust/scripts/stardust/progress.mjs unit done <name> --kind <k> --pages <n> --blocks <n> --verdict "<verdict line>" [--set gates.<w>=<json>]   # 1. (`unit failed` for a failed unit)
node stardust/scripts/replica/foundation-freeze.mjs check                     # 2. after C0's freeze; exit 1 blocks the unit: revert the file or file a request (§ 3)
node stardust/scripts/stardust/unit-commit.mjs <name> [--code blocks/<block>]… --push --message "replica phase 5 C-deliver unit <name>: <verdict line>"   # 3. a unit with pages (an archetype adds its blocks by --code); foundation-chrome, foundation-styles, C0's freeze, C-final: the `git add -A` form above
# 4. ask the boundary, in whatever form the harness provides — a supervisor, if any, ends or continues the session here; none → continue
# 5. next unit — the next cluster report to record, or C-final; nothing else runs on the main agent between units
```

Migrate units (§ 1 row 9) — the same discipline one phase earlier: per unit the `stardust/migrate/progress.json` record (`progress.mjs unit start` when it begins), the checkpoint commit, THEN the next unit (§ 1 row 9's units, in order). A session resumed inside migrate starts from that file and runs only the units not `done`; a unit left `running` re-renders its slugs (`migrate.mjs` is idempotent — unchanged pages are skipped).

```bash
node stardust/scripts/stardust/progress.mjs unit done <name> --ledger migrate --kind <k> --pages <n> --verdict "<verdict line>"   # 1. the unit record
git add -A && git commit -qm "replica phase 5 migrate unit <name>: <verdict line>"   # 2. the checkpoint, same ignore guard as above
# 3. next unit — the next render cluster, assets, or report; a resumed session skips every unit already done
```
