# Phase 5 handoff — contract card (migrate → deploy → rollout)

Everything the replica Phase 5 executor needs from the three sibling skills — rules, commands, exact ledger strings — so no sibling document is read whole. Paths are relative to this file.
For depth, fetch the cited section with `node stardust/scripts/replica/section.mjs <doc> '<heading regex>'`, never the whole document: the `§` text of every citation is the heading (or its regex-safe leading words) and is passed verbatim as the regex.

## 1. Migrate — sibling tier (every non-archetype page of a gated template)

Siblings inherit the archetype's source-fidelity gate; they re-check only what varies per page: content, media, the delivery contract (`../../migrate/reference/fidelity-tiers.md § The three tiers`). The reflex for "page N of a template" is fork the archetype, never re-author.

## 2. Deploy — per page

**Editability contract — node-slotting, never value-slotting** (`../../deploy/SKILL.md § Experience Workspace editability contract`):
- EW1 MOVE authored `h1–h6 / p / ul / ol / pre / blockquote / picture / img` with `append()`/`prepend()`; never rebuild from `textContent`/`innerHTML`, never `cloneNode` + discard, never retag, never `.trim()` displayed text; capture `nextElementSibling` before `append()`.
- EW2 wrappers carry the layout classes; style the authored element through descendant selectors (`.headline :is(h2, h3)`), never a class on it, never `>` / `:first-child` / `:nth-child` on the path to it.
- EW3 CTAs move as their `<p>`. EW4 presentational clones get `stripInstrumentation()`. EW5 exempt text is declared `@ew-exempt <reason>` in the block JSDoc, never dropped. EW6 card-as-link unwraps the inner anchor after reading `href`. EW7 no `<button>`/`<summary>` hosts authored text. EW8 reabsorbed section heads move the wrapper's children. EW9 `decorate()` is re-entrant. EW10 default-content selectors follow the same rules.
- Banned: `slot.textContent = cell.textContent`, `${text}` template interpolation — renders pixel-perfect and is 100 % uneditable (`../../deploy/SKILL.md § Anti-patterns`).

**Decode tier per section** (`../../deploy/SKILL.md § 2b. Section schema`; record the tier in `stardust/eds-conversion-log.md`):
- Template-slotted — replica's default for fixed compositions (hero, band, stat row, chrome): the prototype section's inner DOM as a template of EMPTY slot containers; authored nodes MOVED into them by role.
- Reconstructive — repeat groups only (cards, listings, FAQ): classify by content, never `rows[N]`; segment on the most frequent heading tag; consume every element type or end with a leftovers pass (`../../deploy/SKILL.md § 8. Block JS scaffold`).
- Both tiers, in order: `node stardust/scripts/deploy/section-schema.mjs <protoURL> --out stardust/eds-schema/<page>.json` → write rows and `decorate()` from it → per block `node stardust/scripts/deploy/block-roundtrip.mjs <protoURL> content/<page>.html --blocks <name> --ew` exit 0 (0 structural 🔴, 0 DEAD TEXT / DROPPED CONTENT / DUPLICATED INDEX) → one whole-page run without `--blocks` before any PUT (`../../deploy/SKILL.md § Local QA before deploy`).

**DA media protocol** (`../../deploy/SKILL.md § Images: editorial`):
- Editorial image (anything carrying meaning, hero/CTA backgrounds included): `PUT https://admin.da.live/source/{org}/{repo}/media/<scope>/<file>` — multipart, field name `data`, correct `Content-Type`; JPG/PNG/webp source only; SVG only if pure-vector and under ~40 KB. One command does the whole folder or manifest and prints the URL to author per file: `DA_TOKEN=… node stardust/scripts/deploy/da-media-upload.mjs --org <org> --repo <repo> --scope <name> --dir stardust/current/assets/media` (`--scope` is the folder UNDER `media/`, never `media/<name>` — the path would double and the script refuses it; § 4 table; never a hand-rolled PUT loop — one recorded run wrote a 112-file upload script from scratch).
- Author `<img src="https://content.da.live/{org}/{repo}/media/<scope>/<file>" alt="…">` in the cell; never `/img/…` in content, never imagery baked into block JS by index. Decorative = CSS only.
- Never anonymous-curl `content.da.live` / `admin.da.live` URLs — a 401 there is normal and ingests fine. Verify post-preview only: delivered `.plain.html` has 0 `about:error` and the expected `<img>` + alt count (`../../deploy/da-deploy-protocol.md § Deploy .DA Source API`, step 3b).
- Source-CDN 403/401 = bot wall, NOT missing → rehost from the CAPTURED src (`stardust/current/assets/media/`); omit only on a true 404 after the rendition / `?`-delimiter repairs; when `_crawl-log.json#discovery.fetchTechnique` is `headed-chrome`, verify with the in-page fetch, never a bare curl.
- Images only: video / audio / PDF never ride `content.da.live` (anonymous visitors get 401) — serve them root-relative from the code origin.

**DA deploy protocol** (`../../deploy/SKILL.md § Deploy .DA Source API`; `../../deploy/da-deploy-protocol.md § Deploy .DA Source API`):
- Preconditions: code branch pushed (Code Sync builds it — force with `POST https://admin.hlx.page/code/$ORG/$REPO/$BRANCH/*` → 202 and poll when edited blocks 404); host label `<branch>--<repo>--<org>` ≤ 63 chars; `DA_TOKEN` preflighted (JWT `exp`) and re-checked before each batch — a mid-batch 401 checkpoints the ledger and halts with one instruction, never fails pages red.
- Per-page atomic chain, in order: `localize-links.mjs --source-host <live-host>` over the WHOLE tree, then `--check` exit 0 → `davids-model-lint.mjs` exit 0 → `sanitise.js` → `PUT https://admin.da.live/source/<org>/<repo>/<path>.html` (multipart `data`, `type=text/html`, expect 201) → `POST https://admin.hlx.page/preview/<org>/<repo>/<branch>/<path>` (200) → GET `.plain.html`: 200, `<body>` wrapper, one `<h1>`, 0 `about:error`, no `/img/` → `ai-readability.mjs` code score ≥ 98 → computed-style guard once per template (grid/flex blocks compute `grid`/`flex`, `main .section` > 0, `data-block-name` present, 0 pageerror, every visible image `clientWidth > 0`) → only then `deployed`. Admin 200 ≠ delivered.
- Publish is a decision, not a reflex: stay preview-only (`deploy-batch.mjs --no-publish`) until it is made; `POST https://admin.hlx.page/live/…` is optional per page in the protocol (step 4) but rollout Phase C needs it in the loop when any query-index or chrome document must build from the live tree (`../../rollout/SKILL.md § Phase C`). Record the decision once in `stardust/eds-conversion-log.md` (`../../deploy/SKILL.md § When you finish`).
- More than a few pages: `deploy-batch.mjs`, never a hand-rolled loop; after a transient blip re-run the same command (the ledger skips live pages).

**Boilerplate lint — satisfy it up front, not at commit time.** Blocks and styles lint under the project's own config; never add an `.eslintignore` for runtime files (`../../deploy/SKILL.md § Target runtime`). For the stock boilerplate that is ESLint airbnb-base + Stylelint standard, both blocking: kebab-case CSS class names and selectors; one statement per line — expand one-line multi-statement rules and arrow bodies, the recorded failure class (`../../../notes/deploy-improvements-archive.md § Lint config mismatch`; `../../../../aem/edge-delivery-services/skills/building-blocks/references/css-guidelines.md § Naming Conventions`; `../../../../aem/edge-delivery-services/skills/code-review/references/review-checklist.md § Linting & Style`, `--all`). Once before the checkpoint commit: the boilerplate's own `npm run lint:fix` (its `lint:js -- --fix && lint:css -- --fix`, over `.` and `blocks/**/*.css` + `styles/*.css`), then `npm run lint` — paste only the remaining errors into the conversion log.

**Final gate runs against the PUBLISHED origin**, per delivered page, judged in the published-origin regime — harness numbers understate (`source-fidelity-gate.md § The published-origin gate`) — and never on the harness before the first PUT: the local harness feeds the structural asserts above (`qa-gate.mjs`, `block-roundtrip.mjs --ew`) and nothing pixel-shaped; the delivery pipeline folds section metadata and serves the media the harness cannot, so a harness pixel number is not a verdict and iterating CSS against it is budget spent without a page (`../../deploy/SKILL.md § Local QA before deploy`, scope boundary). The order is: deploy the representative page first, judge it on the preview origin, fix, redeploy — block CSS/JS rides the code-branch push, a content fix re-PUTs that one page, and the ledger skips pages already live (`deploy-batch.mjs`, above). Header and footer bands each ≤ 2 % via `crop-compare.mjs`, at least once per template (`../../deploy/SKILL.md § Step 10 — Reconcile on the DEPLOYED URL`).

**`stardust/rollout/progress.json` — the C-deliver unit ledger** (row C): one object per unit, written by the main agent when the unit starts (`running`) and when it ends (`done` / `failed`), always BEFORE the checkpoint commit and the boundary ask, so a session that ends at the boundary loses nothing and a resumed one reads the file and runs only the units not `done`. `foundation` is C0, `final` is C-final, a cluster unit carries its cluster's name; `verdict` is the subagent's one-line report verbatim; `gates` holds the published-origin numbers behind it (per width the archetype and sibling pixel percentages, the `crop-compare` bands, the chrome-parity delta count). A targeted edit of the one `units.<name>` object, never a rewrite of the file.

```json
{ "units": { "<name>": { "status": "pending|running|done|failed", "kind": "foundation|cluster|final",
  "templates": ["<template>", "…"], "pages": n, "blocks": n, "gates": { "1440": {…}, "360": {…}, "crop": "…", "chrome": "…" },
  "startedAt": "<ISO>", "endedAt": "<ISO>", "verdict": "<cluster>: pages n/n live, blocks k, gate 1440 x% / 360 y%, requests r" } } }
```

**Fan-out discipline (C-deliver, main agent + subagents) — re-read at every session start:**
- **Foundation freeze:** C0 ends with `node stardust/scripts/replica/foundation-freeze.mjs freeze` + the checkpoint commit; until C-final nobody edits a frozen file — `styles/`, `fonts/`, `head.html`, `scripts/`, `blocks/header/`, `blocks/footer/` (the script's default set; `--paths` when a project's foundation lives elsewhere). A main-agent edit after fan-out is the recorded failure: one foundation value changed and one body-class rule added under four running clusters cost two coordination messages and 23 minutes of rework in one cluster.
- **Change requests:** a cluster's foundation finding is ONE appended line in `stardust/rollout/foundation-requests.md` — `- <unit> | <what> | <evidence: instrument + numbers> | <templates affected>`; the cluster ships with a scoped override inside its OWN block CSS and does not wait; never a rule on a frozen file. The main agent applies the queue ONCE at C-final (row C).
- **Mechanical check:** `foundation-freeze.mjs check` runs at every unit end and at C-final start; exit 1 blocks the unit until the file is reverted (`git checkout -- <file>`) or the change becomes a request line.
- **Foundation first:** lint AND commit `styles.css`, header/footer CSS and the contract file BEFORE the first subagent spawns; no edit of a frozen file after fan-out (a recorded rename under three running agents cost seven coordination messages and re-reads).
- **Lint rules in every brief:** lines ≤ 100 chars, CSS custom properties kebab-case; fix a hit with a targeted edit, never a file rewrite; never `--fix` a file another agent is editing.
- **Authored scripts:** `#!/usr/bin/env node`, ESM `import` only (no `require`), run `.mjs` with `node`, `--help` prints usage and exits without touching any file; prefer a shipped script (`../../stardust/reference/scripts-index.md`) to writing one.
- **One-shot helpers live under `/tmp`,** never in the worktree — the checkpoint stages every file the project's `stardust/.gitignore` does not exclude, and its secret-name scan then flags a helper named for tokens at every boundary (a recorded run: ten times, from a stale ignore file).
- **Never `sleep` before `run-bg.mjs wait`;** a propagation wait is a bounded `curl -sf` poll, ≤ 5 s apart, inline.
- **Disjoint clusters spawn concurrently;** a wave waits only on a real dependency (a recorded wave idled 14 min behind an unrelated one).
- **Every tool call under 4 minutes, the main agent's included** (the prompt cache holds 5; `run-bg.mjs wait` returns within 180 s): a long instrument (gate.sh rounds, pixel loops, Playwright captures, deploy batches) goes through `run-bg.mjs start`, and `wait` is the NEXT tool call; never two long instruments as parallel tool calls in one turn, never two `wait`s in one command (a recorded run paid one cache re-write for a 338 s foreground turn on the main agent — a 291 s pixel loop beside a batch start + wait).

## 5. Bookkeeping

Ledger lines go through the master's writer — copy `../../stardust/scripts/ledger.mjs` and `../../stardust/scripts/state.mjs` to `stardust/scripts/stardust/`; one command appends one conformant line to `stardust/status.jsonl` and echoes it. Contract: append-only, one `start` + one `end` per phase, `blocked` with the reason before any halt, file created on first write (`../../stardust/reference/run-status.md § Line shape`; `§ Rules`). `--strict` turns an unknown phase into exit 2 instead of a warning.

```bash
L="node stardust/scripts/stardust/ledger.mjs"
$L replica handoff start --strict
$L rollout A-inventory start --strict;  $L rollout A-inventory end --detail "<n> pages" --artifact stardust/rollout/coverage/pages.json --strict
#   … one start/end pair per phase, strings from § 3: B-block, B2-dynamic, C-deliver, D-site, D2-dynamic, (D3-multilingual), E-full-site, E2-link-audit, F-optimize, G-aem, H-report …
$L rollout C-deliver blocked --detail "DA_TOKEN expired (401) — ledger checkpointed" --strict     # failure path: emit, then halt
$L rollout I-dashboard end --artifact stardust/rollout/dashboard/index.html --strict               # the line supervisors wait for
$L replica handoff end --detail "<n> pages delivered; published-origin gate <result>" --artifact stardust/rollout/ --strict
$L last rollout                                                                                    # read back the latest rollout line
# no project copy yet → the raw form, same fields:
printf '{"ts":"%s","skill":"stardust:rollout","phase":"I-dashboard","event":"end"}\n' "$(date -u +%Y-%m-%dT%H:%M:%SZ)" >> stardust/status.jsonl
```

Page status: pages migrate delivered advance to `migrated` through the lifecycle writer, never a hand edit — `node stardust/scripts/stardust/state.mjs advance <slug…> --to migrated --migrated <path> --skill migrate` (`../../stardust/reference/state-machine.md § Page lifecycle states`).

Checkpoint commit — end of the phase and, inside C-deliver, the end of every unit (below), git repos only; the ignore guard is master Setup step 6, the push is deploy's Code stage (`../../stardust/SKILL.md § Hands-off mode`; `§ Setup`; `../../deploy/SKILL.md § Deploy .DA Source API`):

```bash
git check-ignore -q .env && ! git check-ignore -q stardust/state.json && git add -A && git commit -qm "replica phase 5 handoff: <what landed>" && git push
```

C-deliver units (§ 3 row C) — per unit, in this order: the `progress.json` write, the mechanical check, the checkpoint commit, THEN the boundary ask. The unit is on disk and committed before the session may end, so a resume loses nothing: a session resumed inside C-deliver starts from `stardust/rollout/progress.json` and runs only the units not `done` (an in-flight concurrent unit re-runs from its recorded state — live pages are re-verified, not re-authored). The ask is the one recreate makes after each archetype, and the runner's own instructions decide what its reply means (an empty reply from a listening runner is "still checkpointing", not permission to proceed); with no runner listening — an interactive run, the `curl` fails to connect — the agent proceeds.

```bash
# 1. stardust/rollout/progress.json  units.<name> ← {status: "done", kind, templates, pages, blocks, gates, startedAt, endedAt, verdict}
node stardust/scripts/replica/foundation-freeze.mjs check                     # 2. exit 1 blocks the unit: revert the file or file a request (§ 3)
git add -A && git commit -qm "replica phase 5 C-deliver unit <name>: <verdict line>"   # 3. the checkpoint, same ignore guard as above
curl -s --max-time 300 localhost:8080/boundary                                 # 4. `continue` → next unit; any other reply → end the session here; connection refused (no runner) → next unit
```
