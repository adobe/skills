# Pipeline facts — what the DA → EDS pipeline rewrites on delivery

Read this chapter when a page renders one way in the local harness and another on the preview host: every row is a delivery-time rewrite. This table is the fact catalogue only — the authoring rule for each row lives where the third column points, and the lint id names the detector that runs before the `PUT`. § Local emulation lists which rows the harness now reproduces (`scripts/pipeline-mimic.mjs`) and which it still cannot; § Probe says how the rows marked *assumed* are re-measured on the target stack and where the measured values land.

## Local emulation (`scripts/pipeline-mimic.mjs`)

`build-harness.mjs`, `render-harness.mjs` and `block-roundtrip.mjs` run every row above through `pipeline-mimic.mjs` BEFORE the client runtime mimic, so section tagging, Experience Workspace instrumentation and decode all face the delivered shape; each run prints one line — `pipeline emulation: section-metadata N, meta N, picture N, hoist N, whitespace N, table→block N, icon N, heading-br N, emph-picture N, strip N` — so a page that exercised no rule is visible at a glance. `--no-pipeline` gives the old authored-shape harness for an A/B; `--style-split first-only` flips D7 for a stack measured to keep only the first `style` token; `--no-<rule>` disables one rule. Pinned by `evals/lint/pipeline-mimic-fixture.mjs`: `scripts/fixtures/pipeline-probe{,.plain}.html` (one instance of every rule; the expected file is derived from this table, so rows marked *assumed* rest on it alone) and `scripts/fixtures/pipeline-recorded.plain.html` (a redacted preview recording with `/media_<hash>` sets and real dimensions — every rule is a no-op on it, and the comparison normaliser is exercised against it).

## Probe

The rows above are a catalogue; `node skills/deploy/scripts/pipeline-mimic.mjs --probe --org <org> --repo <repo> --branch <ref>` re-measures them on the target stack (deploy Step 0, optional): it PUTs the probe fixture to a hidden DA path (`/.stardust-probe/pipeline-<ts>`), previews it, reads the delivered `.plain.html`, deletes both, and diffs the page against the mimic rule by rule — `match | differ | unmeasured` per rule, plus `multiValueStyle` (`comma | first-only`, D7's fixture-verify), `spaceStyle` (`hyphen-joined | split`), `zwspSurvives` (D8), `probedAt`, `ref`, `origin` — into `stardust/runtime-contract.json#pipeline` (other keys kept). Preview-only, ≤ 7 requests on the target, none on the source site (D1, D16). Exit `0` recorded, every rule as catalogued; `3` recorded with deviations (one line per differing rule — the contract carries the measured value; the harness narrows its render from `pipeline.multiValueStyle`, the rule text is never auto-edited); `2` no verdict (no token, 401/403, preview or read not 2xx) — `#pipeline` untouched, the catalogue defaults apply, never a FAIL. `--compare <fetched.plain.html>` is the offline form; `--record` rewrites `scripts/fixtures/pipeline-probe.plain.html` from the fetched page so the fixture lint pins a recording instead of a derivation, and every *assumed* row above loses its marker. `probedAt` answers "when was this last measured on this stack".

Still NOT emulated — deployed-URL only: `/media_<hash>` URLs, `<source>` sets and real image dimensions; the real `/nav`, `/footer` and per-page `nav:`/`footer:` chrome as the dev-server harness proxies it (`render-harness --fragments content/` serves them from local content, so only the deployed URL confirms the served chrome); font swap; CLS (#101). The harness number stays provisional — only the published gate counts (A116), one reconcile round is budgeted (A61).
